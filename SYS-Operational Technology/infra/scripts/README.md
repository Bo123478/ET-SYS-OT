## 冒烟测试的四项断言

`smoke-test.ps1` 在 TEST / PROD 部署后执行，挂在工作流末尾。使用服务主体打 Dataverse Web API。

| # | 断言 | 判定标准 |
|---|---|---|
| 1 | Issue 编号格式正确 | 返回值匹配 `INC-\d{4}-\d{6}` |
| 2 | 历史记录自动生成 | 创建后 `bjops_issuehistory` 中存在对应的首条记录 |
| 3 | **防循环生效** | 置 `bjops_automationupdate = 是` 后修改状态，**不产生第二条 Teams 通知** |
| 4 | 权限隔离生效 | 以 Requester 角色身份读取他人 Issue，返回 403 |

第 3 项是重点。防死循环机制如果失效，会导致通知风暴，且在生产环境很难事后补救，因此必须纳入每次部署的自动验证。

第 4 项验证的是"配了角色"与"角色真的生效"之间的差别，不能只看安全角色的配置截图。

## 使用约定

- 脚本**必须**支持通过参数或环境变量接收环境地址与凭据，禁止硬编码。
- 脚本应可重复执行（幂等），失败时返回非零退出码，并由工作流捕获。
- 执行产物输出到 `smoke-output/`（已加入 `.gitignore`）。
- 若在 Linux 代理上运行，Shebang 或调用方式需用 `pwsh` 而非 `powershell`。

## 注意

冒烟测试会在目标环境产生真实数据。建议在 TEST 环境使用固定前缀的测试应用与设备主数据，并在测试后清理；PROD 环境的冒烟应限于只读检查或使用标记为测试的记录。
